## Assembly and routing

Use the ten roadmap layers: runtime safety; relevant company principles; objective/success criteria; project profile/technical policy; issue outcome/acceptance; Harness routing; selected instructions/decisions/skills; role; execution budget/tools; prior concise summary. Preserve source attribution and stable ordering. Project instructions and user task text are explicitly separated from code-owned safety decisions; delimiter placement is not considered a security control.

Use a versioned trusted `registry/context-policy.yml` with task-kind/role/domain-to-source metadata. Support the reviewed H1-H4 context manifest and explicit contained project routes; do not infer file selection by semantic interpretation of arbitrary Markdown tables. Read root primer, mandatory applicable project policy and complete selected skills, not snapshots as replacements. No recursive inclusion of every Markdown link. Permit only registered contained project roots and safe relative text paths; reject links, traversal and secret/auth locations, using Phase M inspection boundaries.

Absent Harness can use an explicit minimal path containing current technical policy and authorized task/scope, with absence recorded. Invalid required routing/instructions or unavailable required skills block; unknown canonical comparison is not authority to adopt a baseline. Personal analysis without an objective remains possible, with optional layers explicitly absent. Write authorization never comes from Harness health.

Default complete rendered-context budget: 500 physical lines and 60000 UTF-8 bytes, configurable downward or upward within code ceilings of 2000 lines / 128000 bytes. Limit selection to 64 sources, individual inspected files to 256 KiB and retain safe bounded read totals. Count safety scaffolding and summaries as well as selected text. Existing 20000-character request ceiling remains separate. Do not claim exact model-token measurement; runtime usage enforcement remains independent. Over-budget mandatory context fails without silent truncation. Any optional omission is deterministic and inspectable.

Routing uses trusted issue classification and scope, not a model's decision about permissions. Trivial low-risk work remains direct; multi-domain/migration/security work explains planning and stronger review requirements. Missing authorization, invalid context or exhausted budgets produces a concrete human-decision reason. Capacity is a snapshot in preview and is rechecked by the existing scheduler, not reserved by preview.

Delegation admission reports benefit, independent acceptance, isolation and available capacity. Trivial work, unverifiable tasks, overlapping writers and insufficient budget are denied. Even a positive decision reports execution unavailable until Phase O; Phase N never spawns workers or overrides the inactive Harness multi-agent boundary.

## Privacy and preview binding

Default client sharing is empty. Consent is category-specific, server-resolved, request-bound and reset when project/task changes. Confidential document bodies are never returned in preview or stored in the manifest. Direct user-authored instructions can still contain sensitive text; known-pattern redaction is not universal data-loss prevention. Automatic company/profile/objective fields need allowlisted selection and sensitivity checks, not indiscriminate JSON serialization.

Provide a protected no-effect POST preview endpoint for analysis and issue requests, plus read-only role availability. The server returns a safe projection and opaque binding fingerprint, not a rendered private prompt. Dispatch reassembles from current trusted state and compares request/role/consent/policy/source and issue scope/revision before creating the task. An expired/changed preview requires explicit regeneration. UI edits invalidate preview and cannot dispatch while stale or blocked. API callers/CLI use the same boundary rather than supplying raw manifests.

## Persistence, execution and resume

Add an optional strict `context_manifest` subdocument with `schema_version: 1` to the task envelope. Existing task files remain the named legacy format and are not rewritten on read. New dispatch always includes a validated manifest, source fingerprints/reasons/sizes/categories, selected role, routing and effective policy/budgets. No source document copies are stored in that manifest. Existing intentionally shared task instructions retain their current privacy/storage boundary; this design does not promise encryption.

Before an attempt, revalidate current role/project/issue authorization and reconstruct context from its attributed sources. Required source or safety-contract changes stop as needs-review before model/worktree effects; do not silently adopt them. Record attempt evidence through existing locked task mutation and append-only events, retaining the known snapshot/event transaction gap. Prior summaries are redacted and capped at 2000 characters. Reuse a runtime thread only for the same admitted safety/scope/consent contract; otherwise require a new governed task. Legacy retries lacking a manifest cannot acquire new assumed consent or permissions.
