# Skill: User Story Writing

## Objective

Turn product intent into clear, testable user stories.

## When To Use

- Preparing tickets, implementation tasks, or acceptance criteria.
- Clarifying expected behavior before engineering work.

## Procedure

1. Identify the user, goal, and value.
2. Write the story in a clear user-centered format.
3. Add acceptance criteria with observable behavior.
4. Include edge cases, permissions, errors, and empty states.
5. Mark dependencies and out-of-scope items.

## Output Format

- Story.
- Acceptance criteria.
- Edge cases.
- Dependencies.
- Out of scope.
- Test notes.

## Limits

- Do not hide unclear requirements behind vague acceptance criteria.
- Do not include implementation details unless they affect behavior.
