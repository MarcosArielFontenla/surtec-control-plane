# Skill: Threat Model

## Objective

Identify meaningful security risks and mitigation options for a system or change.

## When To Use

- Designing authentication, authorization, data storage, integrations, public endpoints, or automation.
- Reviewing a feature that handles sensitive data or privileged operations.

## Procedure

1. Identify assets and trust boundaries.
2. Identify actors and abuse cases.
3. Review authentication, authorization, input handling, storage, logging, and dependency risk.
4. Propose mitigations and residual risks.
5. Mark issues needing human approval.

## Output Format

- Assets.
- Actors.
- Trust boundaries.
- Threats.
- Mitigations.
- Residual risks.
- Required approvals.

## Limits

- Do not claim a system is secure without evidence.
- Do not ignore operational and human-process risks.
