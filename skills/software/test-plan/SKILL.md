# Skill: Test Plan

## Objective

Create a practical test plan that validates behavior and reduces regression risk.

## When To Use

- Planning tests for a feature, bugfix, release, or refactor.
- Reviewing whether existing coverage is enough.

## Procedure

1. Identify the behavior under test.
2. Map acceptance criteria to test cases.
3. Separate unit, integration, end-to-end, manual, and regression tests.
4. Include edge cases, negative cases, and data/state transitions.
5. Identify fixtures, mocks, and test data needs.

## Output Format

- Scope.
- Test matrix.
- Edge cases.
- Regression risks.
- Required test data.
- Manual checks.
- Release confidence notes.

## Limits

- Do not create broad test plans disconnected from user-visible behavior.
- Do not rely only on happy paths.
